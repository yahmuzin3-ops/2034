# Rise of Champions (Fencing Edition)

펜싱 선수를 수집·육성해서 세계 선수권 우승을 노리는 **RPG 육성 시뮬레이션** (Java Swing).
원래 주제인 "동물 육성"을 **펜싱**으로 바꿔서 구현했고, 육성 · 자율 행동 · 전투 · 아이템 · GUI · 멀티스레딩 요구사항을 모두 포함한다.

---

## 1. 실행 방법

- 필요한 것: JDK 11 이상
- 모든 `.java` 파일을 같은 폴더에 두고 컴파일 후 실행

```bash
javac -encoding UTF-8 *.java
java Main
```

- 저장 파일 `savegame.dat`은 실행한 폴더에 생성된다.
- 폰트는 `Malgun Gothic` 기준이다. Windows가 아니라면 `Main.java`의 폰트 이름을 바꾼다.
- 게임 속 하루는 기본 20초다. (`GameEngine.DAY_MILLIS`)

## 2. 게임 설명

| 항목 | 내용 |
|---|---|
| 선수 | 종목(플뢰레/에페/사브르), 성향, 능력치(HP·공격·방어·민첩·기술), 상태(배고픔·피로·기분·부상) |
| 육성 | 훈련 5종, 식단/회복/장비 아이템, 휴식 |
| 자율 행동 | 선수가 상태를 보고 스스로 휴식 / 먹이 탐색 / 놀이 / 개인 연습 |
| 경기 | 최대 3명 팀의 턴제 단체전 (공격·방어·특수기술·아이템) |
| 경제 | 경기 보상과 후원금으로 재화 획득, 상점 구매/판매, 선수 영입, 시설 업그레이드 |
| 이벤트 | 날씨 변화, 부상, 독감, 후원금, 대회 보너스, 팬 응원 |
| 목표 | 업적 7종, 대회 4단계 해금, 시설 확장 |

### 종목과 상성

| 종목 | 특징 | 특수 기술 |
|---|---|---|
| 플뢰레 | 기술이 높음 | 정확한 리포스트 (반드시 명중, x1.5) |
| 에페 | HP·방어가 높음 | 카운터 스톱히트 (x1.4, 사용 후 방어 자세) |
| 사브르 | 공격·민첩이 높음 | 플레슈 돌격 (반드시 명중, x1.9, 반동 피해 5) |

- 상성: **플뢰레 > 사브르 > 에페 > 플뢰레** (유리 x1.25 / 불리 x0.8)
- 특수 기술 쿨타임은 3라운드

### 성향 (자율 행동 기준값과 훈련 효율에 영향)

| 성향 | 휴식 기준(피로) | 연습 기준(기분) | 훈련 보너스 |
|---|---|---|---|
| 열정형 | 80 | 40 | x1.10 |
| 신중형 | 60 | 50 | x1.00 |
| 느긋형 | 50 | 70 | x0.90 |
| 승부욕형 | 75 | 45 | x1.15 |

### 훈련 (피로·배고픔·부상·기분·날씨·훈련장이 효율에 영향)

| 훈련 | 효과 | 피로 |
|---|---|---|
| 풋워크 | 민첩 +3, 기술 +1 | 15 |
| 블레이드워크 | 공격 +1, 기술 +3 | 15 |
| 근력 | 공격 +3, 방어 +1 | 20 |
| 파라드(방어) | 방어 +3, 민첩 +1, 기술 +1 | 15 |
| 지구력 | 최대HP +8, 방어 +1 | 20 |

### 대회

| 대회 | 적 레벨 | 필요 승리 | 보상 |
|---|---|---|---|
| 동네 클럽 대회 | Lv.1 | 0 | 150G |
| 도 대회 | Lv.3~6 | 3 | 400G |
| 전국 대회 | Lv.8~13 | 8 | 900G |
| 세계 선수권 | Lv.14~22 | 20 | 2500G |

### 전투 데미지

```
기본 = 공격 x 1.5 + 기술 x 0.5 - 상대 방어 x 0.6   (최소 3)
최종 = 기본 x 종목 상성 x 등급 보너스 x 스킬 배율 x 랜덤(0.9~1.1)
       피로 70 이상이면 x0.85, 부상이면 x0.8, 크리티컬 x1.5, 상대가 방어 자세면 x0.5
회피 확률 = 5% + (상대 민첩 - 내 민첩) x 1%   (2% ~ 35%)
```

## 4. 코드 구조

```
Main                  실행 시작 (폰트 설정, 이어하기 확인)
MainFrame             상단바 + 사이드 메뉴 + 화면 전환 + 저장/불러오기/종료

[화면]  ScreenPanel(부모) ← HomePanel, AthletePanel, TrainingPanel, ShopPanel,
                            InventoryPanel, MatchPanel, FacilityPanel, GoalPanel
        UI                공통 컴포넌트/색상 도우미

[모델]  Fencer            선수 (능력치, 상태, 성장, 훈련 적용)
        WeaponType        종목 (초기 능력치, 성장률, 특수기술, 상성)
        Personality       성향
        Grade             성장 단계 (신인 → 주니어 → 프로 → 마스터)
        Item ← Food, Medicine, Equipment
        Inventory         아이템 -> 개수
        ItemCatalog       상점 판매 목록
        Weather           날씨 (훈련 효율 배율)
        TrainingType      훈련 종류
        Region            대회 (적 생성, 해금 조건, 보상)
        Achievement       업적

[로직]  GameState         진행 상황 전체 (저장 대상), 훈련/영입/시설/업적
        Battle            턴제 팀 전투 엔진
        Shop              구매/판매
        EventManager      확률 이벤트
        GameEngine        백그라운드 스레드 관리
        GameLog           로그 (스레드 안전)
        SaveManager       직렬화 저장/불러오기
```

### 설계 포인트

- **로직과 화면 분리**: `Battle`, `GameState`, `Shop` 등은 GUI를 전혀 모르기 때문에 콘솔에서도 테스트할 수 있다.
- **화면 공통 틀**: 모든 화면은 `ScreenPanel`을 상속한다.
  - `onShow()`: 화면이 열릴 때 목록 갱신
  - `onTick()`: 0.5초마다 상태 값만 갱신
  - `onStateReplaced()`: 불러오기로 상태가 통째로 바뀔 때
- **확장이 쉬운 구조**: 아이템은 `ItemCatalog`, 대회는 `Region`, 훈련은 `TrainingType`, 업적은 `Achievement`에 항목을 추가하면 된다.

## 5. 멀티스레딩

| 스레드 | 개수 | 역할 |
|---|---|---|
| `fencer-이름` | 선수 수만큼 | 3~4초마다 상태를 보고 자율 행동 결정 (시합 중이면 건너뜀) |
| `game-clock` | 1 | 20초마다 하루 경과, 날씨 변경, 확률 이벤트 |
| EDT (Swing) | 1 | 화면 갱신 (`SwingUtilities.invokeLater`, `javax.swing.Timer`) |

**자율 행동 규칙 (조건문 기반)**

1. HP 30% 미만, 부상 중, 또는 피로가 성향 기준 이상이면 **휴식**
2. 배고픔 60 이상이면 **먹이 탐색** (70% 확률로 성공)
3. 기분 30 미만이면 **놀이**
4. 기분이 성향 기준 이상이고 피로가 낮으면 50% 확률로 **개인 연습**

**동시 접근 보호**

- `Fencer`, `GameState`, `Inventory`의 값을 바꾸는 메서드는 모두 `synchronized`다.
- 여러 스레드가 순회하는 선수 목록은 `CopyOnWriteArrayList`를 쓴다.
- 구매/판매처럼 여러 값을 함께 바꾸는 동작은 `synchronized (state)`로 묶는다.
- 락 순서는 항상 `GameState` → `Inventory` / `Fencer`로 통일해서 데드락을 피한다.
- 저장 중에 값이 바뀌지 않도록 `writeObject`도 `synchronized`로 만들었다.

## 6. 저장 / 불러오기

- `GameState` 객체 하나를 `ObjectOutputStream`으로 직렬화해서 `savegame.dat`에 저장한다.
- 선수, 능력치, 상태, 인벤토리, 재화, 일차, 승리 수, 업적, 시설 레벨이 모두 저장된다.
- 시합 중 여부(`busy`)는 `transient`라서 저장되지 않는다.
- 시작할 때 저장 파일이 있으면 이어하기를 묻고, 종료할 때 저장 여부를 묻는다.
